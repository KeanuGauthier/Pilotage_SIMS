# Jira & Confluence non-regression tests

Automated UI tests for our Jira and Confluence Data Center plugins and macros.
The tests drive Microsoft Edge with Playwright, exactly like a user would, and
the results are sent to Zephyr Squad (one execution per test, one result per step,
with screenshots and logs attached when something fails).

The goal is simple: **when a test passes, the plugin works**. When it fails, the
message should tell you why without having to replay the test by hand.

## Contents of the project

| File | What it is |
|---|---|
| `master.py` | Runs the tests and reports to Zephyr. Also provides `RegressionTest`, used by every test. |
| `actions.py` | The actions used inside the tests (`test.ui.click(...)`, `test.ui.expect_visible(...)`...). |
| `boilerPlate.py` | Template to copy when you write a new test. |
| `selftest_actions.py` | Checks that `actions.py` behaves correctly, on local test pages. |
| `.env.example` | Configuration template. |

The tests themselves are the `ZTEST-*.py` files, usually in a `Confluence` and a
`Jira` folder.

## Installation

You need Python 3.9 or newer and Microsoft Edge.

```
pip install playwright requests python-dotenv
```

Playwright 1.42 or newer is required. Since the tests use the Edge installed on
the machine, there is no need to run `playwright install`.

Then:

1. Copy `.env.example` to `.env` and fill in at least `JIRA_BASE_URL`,
   `JIRA_TOKEN` (a Jira personal access token), `ZEPHYR_PROJECT_ID` and
   `TEST_DIRECTORIES`.
2. Run `python selftest_actions.py`. It should end with `0 problem(s)`. If it
   does not, the problem comes from the machine or the Playwright version, not
   from your tests.

## Running the tests

```
python master.py                  run every test
python master.py --test ZTEST-12  run one test (file name or part of it)
python master.py --list           list the tests found
python master.py --headless       hide the browser (--headed to show it)
python master.py --verbose        more logs
```

`master.py` creates a Zephyr cycle, then runs the tests one after the other and
prints a summary. A single test can also be started directly with
`python Confluence/ZTEST-12_chart.py`. In that case it uses the cycle saved in
`cycle_id.txt`, or creates a new one.

## Writing a test

Copy `boilerPlate.py`, rename it `ZTEST-<number>_<short name>.py` and fill in the
configuration at the top. Each `test.step(n, "...")` block matches step `n` of the
Zephyr test, so keep the same numbering.

```python
with test:
    ui = test.ui

    with test.step(1, "Authenticate and open the page"):
        ui.login_sso(PAGE_URL, expect="#main-content")

    with test.step(2, "The chart macro is displayed"):
        ui.expect_rendered(".chart-macro")
        ui.expect_no_errors()

    with test.step(3, "Change the period"):
        ui.click(by_role("button", re.compile("^(Edit|Modifier)$")), expect="#chart-settings")
        ui.select_option("#period", value="30d")
        ui.click("#chart-settings .save", retries=0, expect_hidden="#chart-settings")
        ui.expect_text(".chart-macro .period", "30")
```

If a step fails, the error is recorded and the next steps still run.

### Authentication

When the browser opens a Jira or Confluence URL without a session, it first
lands on the SSO page where you choose the instance, and a click on "Next" sends
it back to the requested page.

`ui.login_sso(PAGE_URL)` handles that: it opens the page, clicks through the SSO
page, and checks that you end up on the requested page with an authenticated
session. Use it in the first step of every test. Add `user="jdoe"` to also check
the user name, and `expect=` to check an element of the page.

`ui.goto()` goes through the SSO page the same way if it shows up again later
(expired session).

How it works, in case it needs adjusting:

- The SSO page is recognised because it is on another site than the requested
  URL. If that is not the case, set `SSO_PAGE_URL_PATTERN` in `.env` (a regex
  matching its URL).
- The button clicked is the one named "Suivant", "Next", "Continuer", "Continue",
  "Valider", "OK" or "Se connecter" / "Sign in". If yours has another name, set
  `SSO_CONTINUE_SELECTOR` in `.env`, for example `#next-button` or `text=Go`.
- The session check reads the `ajs-remote-user` meta tag that Jira and Confluence
  put in their pages, so it works in French and in English.

## Targeting elements

Every action takes a `target`: the element to act on. The simplest form is a
selector string:

```python
ui.click("#save-button")                     # id
ui.click(".aui-button.save")                 # classes
ui.click("div[data-macro-name='chart']")     # any attribute
ui.click("xpath=//table//tr[2]/td[3]")       # XPath
```

For the harder cases, use the helpers or a `Target`:

```python
by_id("weird.id:with-dots")                 # ids that "#..." cannot handle
by_attr("id", "chart-", match="starts")      # generated ids like chart-8f3a2c
by_class("aui-button", "save")
by_role("button", "Save")                    # buttons, links, tabs, checkboxes...
by_text("Report generated", exact=True)
by_label("Title")                            # form fields
by_test_id("save-btn")                       # data-testid

Target(".cell", within="#results", has_text="Done")   # inside a container, with a text
Target(".row", nth=2)                                  # third visible match (-1 = last)
Target("button", description="Save button")            # nicer name in the reports
```

**Iframes.** Many macros and dialogs live in iframes. Give the iframe with
`frame=`:

```python
Target("canvas.chart", frame="iframe[src*='my-plugin']")
Target("#field", frame=["#outer-frame", "iframe.inner"])   # nested iframes, outermost first
Target("#widget", frame=ANY_FRAME)                         # search the page and every iframe
ui.fill("#tinymce", "Hello", frame=CONFLUENCE_EDITOR_FRAME)  # Confluence editor
```

If you forget the iframe, the error tells you where the element actually is, for
example `found 1 match(es) (1 visible) in an iframe: use frame='#macro-frame-1'`.

**Alternatives.** When an element differs between versions, give a list. The
first one that exists is used:

```python
ui.click(["#new-save-id", "#old-save-id"])
```

**French and English.** The instance can be in either language, so prefer ids,
classes and attributes over texts. When a text is the only way, accept both:

```python
by_role("button", re.compile("^(Save|Enregistrer)$"))
["text=Save", "text=Enregistrer"]
```

Only visible elements are taken into account by the actions. If the target
matches several visible elements, the action refuses to guess and fails: make it
more precise with `within=`, `has_text=` or `nth=`.

## Available actions

All of them are methods of `test.ui`. Timeouts are in milliseconds and most
methods accept `timeout_ms=`.

**Navigation**

| Method | What it does |
|---|---|
| `login_sso(url, user=None, expect=None)` | Opens a page, goes through the SSO page and checks the session is authenticated. |
| `goto(url, expect=None)` | Opens a page (going through the SSO page if needed). Fails on HTTP errors or if you end up on a login page. |
| `reload()` | Reloads the current page. |
| `expect_logged_in(user=None)` | Checks the current page belongs to an authenticated user. |
| `expect_url(text_or_regex)`, `expect_title(...)` | Checks the URL or the page title. |
| `click_new_tab(target)` | Clicks a link that opens a tab and returns the new page (`test.use_page(page)` to switch to it). |

**Checks**

| Method | What it does |
|---|---|
| `expect_visible(target)` | The element is visible on screen: not hidden, not transparent, not covered by something else, not cut off. |
| `expect_all_visible([targets])` | Same for several elements, all problems are reported at once. |
| `expect_hidden(target)` / `expect_absent(target)` | The element is not visible / not in the page at all. |
| `expect_text(target, text, exact=False)` | The displayed text contains (or equals) `text`. Accepts a regex. |
| `expect_no_text(text)` | A text is not displayed anywhere. |
| `expect_rendered(target)` | The macro is visible, done loading, has content and shows no error. |
| `expect_no_errors(within=None)` | No error message is displayed ("Error rendering macro", "Macro inconnue", Java exceptions, AUI error messages...). |
| `expect_count(target, n)` | Number of visible matches. Use `minimum=` / `maximum=` for a range. |
| `expect_table(target, headers=, min_rows=, contains_rows=)` | Checks the content of a table. `read_table(target)` returns it. |
| `expect_image_loaded(target)` | An image is loaded, a canvas is not blank, an svg draws something. |
| `expect_value`, `expect_attribute`, `expect_class` | Value of a field, attribute, CSS class. |
| `expect_enabled`, `expect_disabled`, `expect_checked`, `expect_editable` | State of a field or a button. |
| `expect_no_server_errors()` | No HTTP 5xx answer during the step (done automatically, see `FAIL_STEP_ON_HTTP_5XX`). |
| `expect_no_js_errors()` | No JavaScript exception during the step. |

**Actions**

| Method | What it does |
|---|---|
| `click(target, expect=None, expect_hidden=None, expect_url=None)` | Clicks, then checks the expected result if you give one. |
| `fill(target, text)` | Types into a field or an editable area and checks the value was kept. |
| `type_text(target, text)` | Types key by key, for autocompletes and editor shortcuts. |
| `press(key, target=None)` | Presses a key or a shortcut. |
| `select_option(target, value= / label= / index=)` | Chooses in a native `<select>`. |
| `choose_option(trigger, option, search=None)` | Chooses in a custom dropdown or an autocomplete (AUI, Select2, user picker). |
| `check(target)` / `uncheck(target)` | Ticks or unticks a checkbox. |
| `hover(target, expect=None)` | Hovers an element (tooltips, menus). |
| `drag_and_drop(source, destination, expect=None)` | Drags an element onto another. |
| `upload_file(target, path)` | Uploads a file. |
| `click_and_download(target, expected_extension=".pdf")` | Clicks, downloads and checks the file is a real one. Returns its path. |
| `click_and_handle_dialog(target, expected_message=None)` | Clicks and accepts the browser `confirm()` / `alert()` that opens. |
| `scroll_to(target)` | Scrolls to an element. |

**Utilities**

| Method | What it does |
|---|---|
| `get_text`, `get_value`, `get_attribute`, `count` | Read something from the page. |
| `is_visible(target, timeout_ms=0)` | Returns True/False without failing. For optional things only. |
| `dismiss_if_present(popup, close=None)` | Closes a popup if it shows up ("What's new", onboarding...). |
| `auto_dismiss(popup, close=None)` | Closes a popup automatically whenever it shows up during the test. |
| `wait_for_ready()` / `wait_for_dom_stable(target)` | Waits until the page or an element stops loading / changing. |
| `wait_until(function)` | Waits until your own condition is true. |
| `screenshot(name, target=None)` | Saves a screenshot as evidence. |

## Writing reliable tests

- **End every step with a check.** A click that did not fail proves nothing. Check
  what the user should see afterwards.
- **Give clicks an expected result** (`expect=`, `expect_hidden=` or
  `expect_url=`). It proves the click worked, and a click that had no effect
  (page not fully loaded yet) is repeated once. Use `retries=0` on buttons that
  must not be clicked twice: Save, Submit, toggles.
- **Never wait a fixed time** (`time.sleep`, `wait_for_timeout`). All the actions
  already wait for the page. If you need more, use `wait_for_ready()`,
  `wait_for_dom_stable()` or an `expect_...`.
- **For a macro, use `expect_rendered()` and `expect_no_errors()`.** A visible
  macro container does not mean the macro worked.
- **Avoid `force=True`.** It clicks even when the element is covered, which a user
  could not do.
- **Use `test.ui` rather than raw `page.*` calls.** Raw Playwright calls do not
  have the checks described here.

Checks that something is absent (`expect_hidden`, `expect_absent`,
`expect_no_errors`, `expect_count`) first wait until the page has finished
loading: an error that appears one second after a spinner would be missed
otherwise.

## When a step fails

- The Zephyr step is set to FAIL. The comment starts with the cause, followed by
  the URL and the browser errors (console, failed requests, HTTP errors).
- A full-page screenshot and the error report are attached to the step. The
  Playwright trace is attached to the first failed step.
- Everything is also saved locally in `artifacts/<run date>/<issue key>/`.

The trace replays the whole test, action by action, with the page at each moment:

```
python -m playwright show-trace artifacts/<run>/<issue>/traces/<issue>_trace.zip
```

A passing step can still have warnings, for example when a click had to be
repeated. Zephyr then shows `SUCCESS (with 1 warning(s), check for flakiness)`.
These are worth a look: they usually point to a page that is slow or a test that
could be made more precise.

## Configuration

The main settings of `.env` (see `.env.example` for all of them):

| Setting | Default | Meaning |
|---|---|---|
| `BROWSER_CHANNEL` | `msedge` | Browser used. |
| `HEADLESS` | `false` | Hide the browser. |
| `DEFAULT_TIMEOUT_MS` | `15000` | Default time an action waits for an element. |
| `NAVIGATION_TIMEOUT_MS` | `30000` | Time allowed to load a page. |
| `UI_READY_TIMEOUT_MS` | `8000` | Max time spent waiting for the page to finish loading before an action. Only a warning if exceeded. |
| `UI_SETTLE_MS` | `300` | An element found visible must still be visible after this delay. |
| `UI_CLICK_RETRY_AFTER_MS` | `3000` | When a click has no effect after this delay, it is repeated once. |
| `UI_STRICT_VISIBILITY` | `true` | Set to `false` to fall back to the plain Playwright definition of "visible". |
| `FAIL_STEP_ON_HTTP_5XX` | `true` | A step fails if the server answered with a 5xx error, even if the page looks fine. |
| `FAIL_STEP_ON_JS_ERRORS` | `false` | A step fails on JavaScript exceptions (often noisy in Jira). |
| `IGNORED_HTTP_ERROR_PATTERN` | empty | Regex of URLs whose errors are tolerated. |
| `IGNORED_JS_ERROR_PATTERN` | empty | Regex of JavaScript errors that are tolerated. |
| `TRACE_MODE` | `retain-on-failure` | `on`, `off` or `retain-on-failure`. |
| `ARTIFACTS_DIR` | `artifacts` | Where screenshots, reports and traces are saved. |
| `SSO_CONTINUE_SELECTOR` | empty | Button to click on the SSO page, if the default one is not found. |
| `SSO_PAGE_URL_PATTERN` | empty | Regex of the SSO page URL, if it is on the same site as Jira/Confluence. |

## Self-test

`selftest_actions.py` starts a small local web server with pages built to trap
a test: a button that is transparent or hidden under an overlay, content inside
a 0px-high iframe, an error that shows up after a spinner, an HTTP 500 behind a
page that looks fine, an HTML error page downloaded as `.pdf`, an SSO page with a
"Suivant" button, and so on. For each case it checks that the actions pass or fail as they should.

Run it after changing `actions.py`, after upgrading Playwright or Edge, or on a
new machine. It needs neither Jira nor Zephyr.

## Common messages

| Message | What to do |
|---|---|
| `matches several visible elements` | The target is ambiguous. Add `within=`, `has_text=` or `nth=`. |
| `... in an iframe: use frame=...` | The element is in an iframe. Add the suggested `frame=`. |
| `is covered by div.aui-blanket` (or another element) | Something is on top of the element: an open dialog, a popup, a banner. Close it, or use `dismiss_if_present` / `auto_dismiss` if it is not part of the test. |
| `is transparent` / `is not painted at its position` / `is outside the visible area` | The element exists but a user cannot see it. Usually a real bug, or a section that must be expanded first. |
| `the browser is on a login page` | The session is not authenticated. Check the SSO step. |
| `... is not a Jira/Confluence page. If it is the SSO page, set SSO_CONTINUE_SELECTOR` | The SSO button was not recognised. Set `SSO_CONTINUE_SELECTOR` in `.env`. |
| `Page still busy after ... ms` (warning) | A spinner or a request never finished. If it is a normal background request, add it to `DEFAULT_IGNORED_PENDING_URLS` in `actions.py`. |
| `Server error response(s) received` | The server answered with a 5xx error during the step. If it is unrelated to the plugin, add the URL to `IGNORED_HTTP_ERROR_PATTERN`. |
| `Typed ... but it contains ...` | The field did not keep the value. If the application reformats it on purpose, use `fill(..., expected_value=...)`. |
