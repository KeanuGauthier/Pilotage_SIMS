# Playwright Non-Regression Test Framework

## Purpose

This project runs Playwright-based non-regression tests against intranet applications and reports their results to Zephyr Squad Server/Data Center.

`master.py` is the central runtime. It creates the Zephyr test cycle, discovers and runs test scripts, controls Microsoft Edge, updates every Zephyr test step, and collects diagnostics. `exempleZtest.py` is the template to copy when creating a test.

The framework is designed for Windows, Python 3.9, Microsoft Edge, and an environment without Internet access. It uses the installed Edge channel and does not require a browser download through `playwright install`. Playwright officially supports controlling Microsoft Edge installed on the machine through the `msedge` channel; enterprise browser policies can still affect automation ([Playwright browser documentation](https://playwright.dev/python/docs/browsers#google-chrome--microsoft-edge)).

## Project files

| File | Responsibility |
| --- | --- |
| `master.py` | Browser lifecycle, Zephyr API client, step execution, artifacts, test discovery, and command-line runner |
| `exempleZtest.py` | Template copied for each new automated Zephyr test |
| `.env` | Local URLs, token, paths, and runtime configuration; never commit this file |
| `.env.example` | Safe configuration reference without credentials |
| `requirements.txt` | Python dependencies required by the framework |
| `artifacts/` | Screenshots, error reports, and Playwright traces generated during execution |

`generalBoilerplate.py` is retained only as the original reference. It is not used by the new runtime.

## Prerequisites

- Windows with Microsoft Edge installed in its standard location
- Python 3.9
- Access to the Jira and Zephyr intranet endpoints
- A Jira personal access token authorized to read test issues and update Zephyr executions
- The Python packages listed in `requirements.txt`

## Offline installation

If the target machine has no Internet access, prepare the dependencies on a connected Windows machine using the same Python version and architecture:

```powershell
py -3.9 -m pip download --dest wheelhouse -r requirements.txt
```

Copy the project and the `wheelhouse` directory to the intranet machine, then install exclusively from the copied packages:

```powershell
py -3.9 -m pip install --no-index --find-links=wheelhouse -r requirements.txt
```

Do not run `playwright install`. The framework launches the existing Microsoft Edge installation with `channel="msedge"`.

## Configuration

Create the local configuration from the example:

```powershell
Copy-Item .env.example .env
```

Update `.env` with the real values. The most important settings are:

| Setting | Description | Typical value |
| --- | --- | --- |
| `JIRA_BASE_URL` | Jira base URL, including `/jira` when used by the server | `https://jira.example.intranet/jira` |
| `JIRA_TOKEN` | Personal access token used for Jira and Zephyr API calls | Secret value |
| `ZEPHYR_PROJECT_ID` | Numeric Jira project ID used by Zephyr | `80302` |
| `ZEPHYR_VERSION_ID` | Zephyr version ID; `-1` means the unscheduled version | `-1` |
| `TEST_DIRECTORIES` | Semicolon-separated directories containing test scripts | `C:\NRT\Confluence;C:\NRT\Jira` |
| `TEST_FILE_PATTERN` | Recursive filename pattern used to discover tests | `*Ztest.py` |
| `HEADLESS` | `false` during development and `true` on the VM | `false` |
| `VERIFY_TLS` | Whether API calls validate the server certificate | `true` |

Keep tokens and credentials in `.env`, not in Python files. `.env` is ignored by Git. Prefer installing the intranet certificate authority on Windows instead of setting `VERIFY_TLS=false`.

The former `CONFLUENCE_DIR` and `JIRA_DIR` variables are still supported when `TEST_DIRECTORIES` is absent. This eases migration from the Selenium configuration.

## Creating a test

1. Copy `exempleZtest.py` and give the new file a name that matches `TEST_FILE_PATTERN`, for example `loginZtest.py`.
2. Set `ISSUE_KEY`, `TEST_NAME`, and `BASE_URL`.
3. Ensure the test steps already exist in Zephyr and use the same order in the Python script.
4. Generate browser actions into a temporary file with Codegen.
5. Paste only the page actions into the corresponding `with test.step(...)` block.
6. Add explicit `expect(...)` assertions that prove the expected result.
7. Replace the template `NotImplementedError` and add or remove step blocks as required.

Example Codegen command:

```powershell
playwright codegen --channel msedge -o generated_test.py https://application.example.intranet
```

Codegen generates imports, a Playwright startup function, browser creation, page actions, and browser cleanup. Copy only statements that act on `page`, such as:

```python
page.get_by_role("button", name="Sign in").click()
page.get_by_label("User name").fill("example")
expect(page.get_by_role("heading", name="Home")).to_be_visible()
```

Do not copy `sync_playwright()`, `chromium.launch(...)`, `browser.new_context()`, `context.close()`, or `browser.close()`. `RegressionTest` already owns those resources.

Each test step has this form:

```python
with test.step(1, "Open the application"):
    page.goto(BASE_URL)
    expect(page.get_by_role("heading", name="Home")).to_be_visible()
```

There is no need to add `try/except` around a step. `master.py` records the exception, reports the failed step, and continues with the next block. Steps should nevertheless be as independent as practical: if step 2 requires data created by failed step 1, step 2 may also fail.

### Iframes

Use the `frame_locator` code generated by Playwright:

```python
with test.step(3, "Validate content inside the embedded page"):
    frame = page.frame_locator("#application-frame")
    expect(frame.get_by_role("heading", name="Dashboard")).to_be_visible()
```

### New tabs and popup windows

When an action opens a new tab, make it the current diagnostic page so failure screenshots and URLs refer to that tab:

```python
with test.step(4, "Open the details page"):
    with page.expect_popup() as popup_info:
        page.get_by_role("link", name="Details").click()
    page = test.use_page(popup_info.value)
    expect(page).to_have_title("Details")
```

## Running tests

List discovered tests without contacting Zephyr:

```powershell
py -3.9 master.py --list
```

Run all discovered tests in one new Zephyr cycle:

```powershell
py -3.9 master.py
```

Run one test by filename, stem, or an unambiguous part of its name:

```powershell
py -3.9 master.py --test loginZtest
```

Override the browser mode for one run:

```powershell
py -3.9 master.py --test loginZtest --headed
py -3.9 master.py --headless
```

A copied test can also be launched directly during development:

```powershell
py -3.9 loginZtest.py
```

A direct run reuses the cycle ID stored in `cycle_id.txt`. If that file does not exist, the test creates a new cycle automatically.

The exit code is `0` when all steps and Zephyr updates succeed, `1` when a test fails, and `2` when the master configuration or setup is invalid. `master.py` continues through the remaining test scripts after a failure and prints a final summary.

## Zephyr reporting workflow

For each full run, `master.py`:

1. creates one Zephyr cycle;
2. starts every selected script with the same cycle ID;
3. creates one Zephyr execution for the script's `ISSUE_KEY`;
4. marks the execution as in progress;
5. initializes Zephyr step-result IDs through `expand=checksteps`;
6. marks each step as passed or failed;
7. attaches failure diagnostics to the failed step;
8. marks the global execution as passed or failed.

The `expand=checksteps` API replaces the former Selenium automation that opened the Zephyr interface only to initialize step IDs. SmartBear documents this endpoint specifically for materializing step results without viewing the execution in Jira ([SmartBear ZAPI guidance](https://support.smartbear.com/zephyr-enterprise/faq/no-data-returned-test-step-id-s-are-not-created-on/)). It is more stable because it does not depend on page layout or CSS selectors. If an older internal Zephyr version does not support it, set `ZEPHYR_UI_FALLBACK_ENABLED=true` and configure `ZEPHYR_TEST_SUMMARY_URL`; the fallback uses Playwright to reproduce the former interface workflow.

## Failure diagnostics

For every failed step, the framework creates and uploads:

- a full-page PNG screenshot;
- a UTF-8 text report containing the exception, complete Python traceback, current URL, browser console errors, unhandled page errors, and failed network requests.

When `TRACE_MODE=retain-on-failure`, one Playwright trace is retained for a failed scenario and attached to its first failed Zephyr step. Open it locally with:

```powershell
playwright show-trace artifacts\<run>\<issue-key>\traces\<issue-key>_trace.zip
```

The command opens Playwright's local Trace Viewer ([Trace Viewer documentation](https://playwright.dev/python/docs/trace-viewer)). Traces can contain page snapshots and entered values. Treat the `artifacts` directory as potentially sensitive and do not commit or distribute it unnecessarily.

## Troubleshooting

### No tests are discovered

Run `master.py --list`, then check `TEST_DIRECTORIES` and `TEST_FILE_PATTERN`. Multiple Windows directories must be separated with semicolons.

### A Python step number does not exist in Zephyr

The first Python block maps to the first Zephyr step, the second block to the second Zephyr step, and so on. Add the missing step in Zephyr or correct the Python number. Reporting mismatches cause a non-zero result to prevent false passes.

### Zephyr returns no step-result IDs

First confirm that the Zephyr issue contains test steps. If the internal Zephyr version rejects `expand=checksteps`, enable the documented UI fallback in `.env` and supply the test-summary URL used by the former Selenium implementation.

### Microsoft Edge does not start

Confirm that Edge is installed normally and that `BROWSER_CHANNEL=msedge`. The Playwright Python package must be installed, but Playwright's bundled Chromium browser is not required.

### API calls fail with certificate errors

Install the intranet certificate authority in the Windows trust store. `VERIFY_TLS=false` is available for exceptional local troubleshooting but reduces connection security.

## Why pytest is not included

Pytest is an excellent general-purpose Python test runner, particularly for fixtures, parameterized tests, and CI pipelines. This project already has a runner (`master.py`) and a required one-to-one mapping between business steps and Zephyr step results. Adding pytest now would introduce a second execution and reporting model without simplifying the current workflow. It can be introduced later if the test suite develops requirements that justify it.

## About `pyproject.toml`

`pyproject.toml` is the modern standard configuration file for Python projects. It can define project metadata, the supported Python version, dependencies, packaging rules, and settings for tools such as pytest, formatters, and linters.

This project intentionally uses `requirements.txt` instead. It is simpler for a script-based, offline deployment and works directly with a copied wheel directory. A `pyproject.toml` would become useful if the framework were packaged as an installable internal Python library or if several development tools needed centralized configuration.

## Maintenance guidelines

- Keep shared browser, Zephyr, retry, and artifact behavior in `master.py`.
- Keep business-specific selectors and assertions in individual test files.
- Prefer Playwright role, label, placeholder, and test-ID locators over long CSS or XPath selectors.
- Use Playwright assertions (`expect`) instead of fixed `time.sleep` delays.
- Never suppress a failure manually unless the behavior is explicitly optional and documented.
- Never place tokens, passwords, or production data in source files.
